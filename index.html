Why cyba-dojo

Weaknesses are in usual features.

Most tutorials show one weakness at a time. Real applications are different. In the dojo, each weakness gives you access to the next weakness. The Mission Console shows you where to look.

STEP 1

Sign in as a student

Start the campus. Then click the sign-in button. The form contains student1 / student1.

STEP 2

Do the current act

mark doneThe next act opens.

When you find the weakness, click Mark done. The console does not check your attack. It trusts you.

defendName the control.

After you mark an act done, the console asks you to name the control that stops the attack. Answer first. Then open the control and compare.

CAUTIONThe dojo has intentional weaknesses. Run it only on a computer and a network that you control. Do not connect it to the internet. Attack only systems that you own or have permission to test.

Features

One campus with many weaknesses.

01

34 weaknesses

Each weakness comes from a possible design error. Each weakness has an id, a source location and a class.

02

Four datastores

PostgreSQL, MySQL, MongoDB and SQLite each hold the data for one or more campus areas. Each injection is different.

03

A storyline with seven acts

The acts go from reconnaissance to superadmin. Each act has a hint and a Defend step. Thus you always know where to start.

04

A test for each weakness

An end-to-end test suite does all the acts. Each of the 34 weaknesses has a test that makes sure it operates as the map shows.

The Semester Heist

Seven acts in three rings.

You start outside the campus and move to the center. Each act opens the next act. For the first acts, you use only a browser. For the last acts, you use curl or the browser developer tools.

1

Go into the campus

Find the attack surface. Then open a student session.

  • ACT 0Case the campus: reconnaissance and information disclosure.
  • ACT 1Get a foothold: authentication weaknesses.
2

Increase your access

Read the data of other students. Change your role. Then use the staff functions.

  • ACT 2Read the class: broken object level authorization.
  • ACT 3Change who you are: mass assignment.
  • ACT 4Rewrite the record: broken function level authorization.
3

Control the center

Attack campus security. Send requests to internal services. Then find why no alarm occurred.

  • ACT 5Breach campus security: NoSQL injection and broken cryptography.
  • ACT 6Reach inside & go quiet: SSRF and missing logs.

Quickstart

Start the dojo.

You must have Docker with Compose. One command starts the application, PostgreSQL, MySQL and MongoDB. Without Docker, npm run dev starts only the student areas.

Clone the repository

Clone the repository. Then go into the directory.

git clone https://github.com/cybagard/cyba-dojo
cd cyba-dojo

Start the campus

This command starts the app and the three databases as containers. SQLite runs inside the app. Thus the full storyline uses all four.

docker compose up -d --build

Open the portal

Open http://localhost:3000/. The first page is Act 0. Sign in to open the Mission Console.

# portal  http://localhost:3000/
# login   student1 / student1
# api     http://localhost:3000/apidoc

Add an attack computer or a WAF (optional)

A Kali attacker box and a ModSecurity WAF are optional profiles in front of the app. They join the same network.

docker compose --profile attacker --profile waf up -d --build
