Why cyba-dojo

Weaknesses are in usual features.

Most tutorials show one weakness at a time. Real applications are different. In the dojo, each weakness gives you access to the next weakness. The Mission Console shows you where to look.

Features

One campus with many weaknesses.

01

34 weaknesses

Each weakness comes from a possible design error. Each weakness has an id, a source location and a class.

02

Four datastores

PostgreSQL, MySQL, MongoDB and SQLite each hold the data for one or more campus areas. Each injection is different.

03

A storyline with seven acts

The acts go from reconnaissance to superadmin. Each act has a hint. Thus you always know where to start.

04

A test for each weakness

An end-to-end test suite does all the acts. It makes sure that each weakness operates as the map shows.

Vulnerability map

The map shows the location, not the attack.

Each entry gives the location and the class of a weakness. It does not give the payload. You must find the technique.

  • ✓
    Each weakness has an id. Use the ids to grade a class or a CTF. Do not publish the payloads.
  • ✓
    One route shows the correct method. GET /api/v1/library/list/book/:id uses a bound parameter. Compare it with the routes that have injection.
  • ✓
    One component is old, on purpose. marked has a version with known weaknesses. Your dependency scanner shows it.

The Semester Heist

Seven acts in three rings.

You start outside the campus and move to the center. Each act opens the next act. For the first acts, you use only a browser. For the last acts, you use curl or the browser developer tools.

1

Go into the campus

Find the attack surface. Then open a student session.

  • ACT 0Examine the campus: reconnaissance and information disclosure.
  • ACT 1Sign in: authentication weaknesses.
2

Increase your access

Read the data of other students. Change your role. Then use the staff functions.

  • ACT 2Read the class: broken object level authorization.
  • ACT 3Change your identity: mass assignment.
  • ACT 4Change the record: broken function level authorization.
3

Control the center

Attack campus security. Send requests to internal services. Then find why no alarm occurred.

  • ACT 5Attack campus security: NoSQL injection and broken cryptography.
  • ACT 6Go inside and stay hidden: SSRF and missing logs.

Quickstart

Start the dojo.

You must have Docker with Compose. One command starts the application, PostgreSQL, MySQL and MongoDB. Without Docker, npm run dev starts only the student areas.

Clone the repository

Clone the repository. Then go into the directory.

git clone https://github.com/cybagard/cyba-dojo
cd cyba-dojo

Start the campus

This command starts the four datastores. The full storyline uses all four.

docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build

Open the portal

Open http://localhost:3000/. The first page is Act 0. Sign in to open the Mission Console.

# portal  http://localhost:3000/
# login   student1 / student1
# api     http://localhost:3000/apidoc

Add an attack computer or a WAF (optional)

These Compose files add a Kali Linux container and a ModSecurity WAF. They use the same network.

docker compose -f docker-compose.yml -f docker-compose.dev.yml \
  -f docker-compose.mod_security.yml -f docker-compose.kali.yml up -d --build
