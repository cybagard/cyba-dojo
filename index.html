Why cyba-dojo

Real bugs hide in ordinary features.

Most tutorials show you one bug in isolation. Real systems are not that tidy. In the dojo, one small mistake gives you the foothold for the next.

01

One campus, not one bug.

Students, a library, a registrar, coursework, campus security and single sign-on. Each feature has a weakness that grew from a plausible design decision.

02

A path, not a blank page.

The Mission Console shows your progress, the current act and a hint. One button takes you to the exact screen that you need.

03

Proof, not promises.

An end-to-end suite boots all four databases and walks the full storyline. It asserts that every weakness in the map behaves as written.

The Semester Heist · Guided path

Seven acts from visitor to superadmin.

You cannot skip floors. The first acts need only a browser. The last acts need curl or your browser's developer tools.

ACT 0

Case the campus.

Reconnaissance and information disclosure. Find the shadow API next to the published one.

ACT 1

Get a foothold.

Authentication weaknesses. Three different failure classes guard the same door.

ACT 2

Read the class.

Broken object-level authorization. The server never asks whether the record is yours.

ACT 3

Change who you are.

Mass assignment. One request changes your role for the rest of the system.

ACT 4

Rewrite the record.

Broken function-level authorization. Reach the staff endpoints that the UI never shows you.

ACT 5

Breach campus security.

NoSQL injection and broken cryptography. Two trust failures each defeat a login.

ACT 6

Reach inside and go quiet.

Server-side request forgery and missing logging. Find out why nobody noticed.

EVERY ACT

Then flip the question.

Each act ends with one question: what control should have stopped you? The learning sticks there.

Get started · Docker Compose

Start the campus with one command.

The command starts the app, PostgreSQL, MySQL and MongoDB. Then open http://localhost:3000/ and read Act 0 on the landing page.

CAUTIONThe dojo is full of holes by design. Run it on a machine and a network that you control. Never expose it to the internet. Only test systems that you own or have permission to test.

Get the code

Clone the repository and go into it.

$ git clone https://github.com/cybagard/cyba-dojo
$ cd cyba-dojo

Start the full campus

Docker with Compose runs all four datastores. You need this for the full storyline.

$ docker compose -f docker-compose.yml \
    -f docker-compose.dev.yml up -d --build

Sign in as a student

The form is already filled in. Click the button and the Mission Console opens.

# portal   http://localhost:3000/
# login    student1 / student1
# api      /api/v1  ·  /apidoc
For learners, teachers and defenders

Built to teach, not only to break.

The dojo suits a first week in application security. It also suits a graded class or a small CTF.

  • ✓
    Hints are one click away. The Mission Console keeps a "look for" hint next to the current act. You are guided, not stranded.
  • ✓
    You can grade without a payload. Each weakness has a stable id and a place in the storyline. Grade on which weakness a learner found and where.
  • ✓
    Good code is there for contrast. GET /api/v1/library/list/book/:id uses a parameterised query. Compare it with the injectable login.
  • ✓
    You can add an attacker box or a WAF. Optional Compose files add a Kali Linux container and a ModSecurity WAF on the same network.
  • ✓
    The stack is current, with one exception. marked stays on an old, known-vulnerable version on purpose. Your dependency scanner flags it. That is the lesson.
